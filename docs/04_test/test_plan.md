# テスト計画書

- 版数: v1.0
- 作成日: 2026-08-08
- 関連: [処理定義書](../03_detail_design/process_design.md), [実装スコープ](../02_basic_design/00_implementation_scope.md)

## 1. テストの目的

個人開発・小規模チームでの継続的な保守を前提に、以下を目的として自動テストを整備する。

1. 機微情報(パスワード等)を保存しないという設計方針(要件定義書5.4)がコード変更によって
   崩れていないことを継続的に検証する
2. 主要なドメインロジック(バリデーション・ダッシュボード集計・紐づけ関係のグラフ探索・
   エクスポート整形)の振る舞いを固定し、リグレッションを防ぐ
3. CI(GitHub Actions)のゲートとして自動実行し、mainブランチへのマージ・デプロイ前に
   問題を検知する

## 2. テストツール・方針

| 項目 | 内容 |
|---|---|
| テストランナー | Vitest(要件定義書の指示通り導入) |
| テスト環境 | `jsdom`(コンポーネントテスト用)。ロジック単体テストはNode環境と同様に動作する純粋関数のため環境非依存 |
| コンポーネントテスト | `@testing-library/react` + `@testing-library/jest-dom` を用いた最小限のレンダリングテスト |
| カバレッジ対象 | `shared/`配下のドメインロジックを最優先。`functions/api/`のHTTPハンドラ自体はCloudflare実行環境依存が強いため、ロジックを`shared/`に切り出した上でそちらをテストする方針とする(処理定義書1章参照) |
| 実行方法 | `pnpm test`(watchモード) / `pnpm test:run`(CI向け単発実行) |

## 3. テストレベルと範囲

| レベル | 対象 | 本プロジェクトでの扱い |
|---|---|---|
| 単体テスト | `shared/*.ts` の純粋関数、`src/lib/lock.ts` | vitestで実装(必須) |
| コンポーネントテスト | 主要画面コンポーネントの最小レンダリング確認 | vitest + Testing Libraryで一部実装(必須) |
| 結合テスト(API) | Cloudflare Pages Functions + D1 の結合動作 | `wrangler pages dev`によるローカル動作確認で代替し、自動テストのスコープ外とする(個人開発規模のため、詳細は[実装スコープ](../02_basic_design/00_implementation_scope.md)の考え方に準拠) |
| E2Eテスト | ブラウザ操作によるシナリオテスト | 初期リリースではスコープ外。将来的な拡張時に検討 |

## 4. 重点テスト項目(要件定義書との対応)

| # | 要件定義書項番 | テスト内容 |
|---|---|---|
| 1 | 5.4 | `login_methods`のドメイン型・DBスキーマにパスワード実値を保持するフィールドが無いこと(型定義のレビュー+バリデーションのテストで間接的に担保) |
| 2 | 5.2 | ID_PW方式の場合に`credentialManager`が必須であることのバリデーションテスト |
| 3 | 5.3 | 循環した紐づけ関係が登録できないことのテスト(`wouldCreateCycle`) |
| 4 | 5.3 | 「このアカウントを失うと、どのサービスに影響するか」の逆引き(`getDescendants`)のテスト |
| 5 | 5.5/5.6 | 休眠アカウント・要確認・期限間近の集計ロジック(`buildDashboardSummary`)のテスト |
| 6 | 5.7 | CSV/JSONエクスポートのフォーマット(`toExportCsv`/`toExportJson`)のテスト |
| 7 | 6(非機能) | マスターパスワードロックの正常系・異常系(`hashPassword`/`tryUnlock`)のテスト |

## 5. 実行タイミング

- ローカル開発時: 実装のたびに `pnpm test` を実行
- CI: 全ブランチへのpush、およびmainへのPull Requestで `pnpm test:run` を自動実行([CI/CD設計書](../03_detail_design/ci_cd_design.md)参照)
- リリース判定: CIのテストジョブが成功していることをmainマージの必須条件とする

## 6. 完了基準

- 4章の重点テスト項目がすべて自動テストとして実装され、成功していること
- `pnpm test:run` がCI上で成功すること
- `pnpm audit --audit-level=high` で高リスク以上の脆弱性が検出されないこと
