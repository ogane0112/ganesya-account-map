## 1. アクセス制御 設定完了チェックリスト

要件定義書9.3節の通り、以下の両方が設定済みであることを定期的に確認する。

- [ ] カスタムドメイン(`accounts.<yourdomain>`)用のCloudflare Accessアプリケーションが設定されている
- [ ] `*.pages.dev` ドメイン用のCloudflare Accessアプリケーションが設定されている(裏口対策)
- [ ] Accessポリシーの許可対象が自分のメールアドレスのみに限定されている

## 2. 定期運用タスク

| 頻度 | タスク | 手順 |
|---|---|---|
| 月1回程度 | データのエクスポート・バックアップ | 設定画面(SC-06)からJSON形式でエクスポートし、任意の安全な場所に保管する |
| 月1回程度 | 依存ライブラリの脆弱性確認 | `pnpm audit` をローカルで実行、またはDependabotからの提案PRを確認しマージする |
| 週1回程度 | Dependabotの提案確認 | 提案されたPRの内容(変更点・CVE有無)を確認し、問題なければ手動マージする(自動マージはしない) |
| 随時 | ダッシュボードの休眠/要確認アカウント確認 | アプリのダッシュボード画面で休眠・要確認・期限間近のアカウントを確認し、必要に応じてステータスを更新する |

## 3. インシデント対応

### 3.1 デプロイ後に不具合が発覚した場合

1. Cloudflare Pagesダッシュボードの「Deployments」から直前の正常なデプロイを選択し、
   「Rollback to this deployment」を実行する
2. 原因を調査し、修正PRを作成してCI/CDで再デプロイする

### 3.2 データを誤って削除・破損した場合

1. 直近のエクスポートファイル(2章のバックアップ)からアカウント情報を手動で復旧する
2. より厳密な復旧が必要な場合は `wrangler d1 export account_map_db --remote --output=backup.sql` で
   取得できるスナップショット(定期取得している場合)から復元する

### 3.3 マスターパスワードを忘れた場合

- アプリのロックはブラウザの `localStorage` にのみハッシュを保持する簡易ロックのため、
  ブラウザの開発者ツールから `localStorage.removeItem('accountMap.lockHash')` を実行することで
  ロックを解除できる。この操作は本人のみが実施できることを前提とする
  (処理定義書2.6節に記載の通り、主たるアクセス制御はCloudflare Access側で担保している)

## 4. 制限事項(利用者への周知事項)

- マスターパスワードロックは端末ローカルの簡易ロックであり、本アプリのAPIエンドポイントを
  直接呼び出せば理論上回避可能である。実運用上のアクセス制御はCloudflare Accessに依存する
- 本アプリはパスワードの値自体を保存しない設計のため、パスワードの変更・確認は
  設定した保存先ツール(1Password等)側で行う必要がある(要件定義書5.4節)
